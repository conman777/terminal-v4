# T3 capability comparison

This is a **source inventory**, not a tested feature-parity or visual-design
certification. The T3 reference is pinned to
[`5f64c5eb299a23d278ef043c416bd4dc801bc53c`](https://github.com/pingdotgg/t3code/tree/5f64c5eb299a23d278ef043c416bd4dc801bc53c).
V4 references are to the shared working tree (branch `fix/macos-app-verification`,
HEAD `97344b0`, possibly with uncommitted edits) with the following rows updated by targeted source review,
not to the Tailscale deployment. Changes made concurrently can invalidate
these observations. A row marked **Partial** establishes only the capabilities
named in that row; it does not establish equivalent semantics, availability or
visual similarity. **Unknown** means the relevant behavior was not established;
**Missing** means no counterpart was found in the inspected frontend source.
All cited V4 source paths were confirmed to exist at the time of this review. The T3 files in the Composer and Project/terminal sections were fetched and read at the pinned commit (the `ChatComposer.tsx` fetch covered only its first ~100 KB of 156 KB); V4 comparisons are by targeted source search, not by running the apps.

The T3 mobile references below are from its native mobile source. They are useful
design and behavior evidence, but do not prove what the T3 web app supports in a
mobile browser. V4 mobile references describe its responsive browser path.

Approved suggestions remain available for the owner to add explicitly again if a response was lost; check the draft first to avoid duplicates. Claim and settlement use zero-wait database admission and transactional updates; contention returns a temporary failure. A temporary lookup or settlement failure or cancellation schedules best-effort release of only the exact still-active provisional link claim through a single worker with a bounded queue and bounded retries. If the queue fills, the worker cannot start, storage remains unavailable, or the process crashes, the link remains consumed, and a lost response after successful settlement remains ambiguous and does not make the link reusable. Secrets and credentials are stored as SHA-256 hashes, the link secret is compared in constant time after lookup, exchange and read/suggest are rate limited, expired rows are swept (hashes cleared immediately, rows kept 30 days for audit), and an owner audit trail is listed in the panel. Limits: polling (default 3 s) rather than a push stream; single guest per link; rate limits are in memory per process; owner sign-out and password change revoke active and unredeemed shares; remote (paired) environments cannot issue shares. Complete private-key opening markers are handled across message and page boundaries, but already delivered partial marker fragments cannot be recalled. |
