# T3 capability comparison

This is a **source inventory**, not a tested feature-parity or visual-design
certification. The T3 reference is pinned to
[`5f64c5eb299a23d278ef043c416bd4dc801bc53c`](https://github.com/pingdotgg/t3code/tree/5f64c5eb299a23d278ef043c416bd4dc801bc53c).
V4 references are to the shared working tree (branch `fix/macos-app-verification`,
HEAD `61f1e21`, possibly with uncommitted edits) re-checked during this review,
not to the Tailscale deployment. Changes made concurrently can invalidate
these observations. A row marked **Partial** establishes only the capabilities
named in that row; it does not establish equivalent semantics, availability or
visual similarity. **Unknown** means the relevant behavior was not established;
**Missing** means no counterpart was found in the inspected frontend source.
All cited V4 source paths were confirmed to exist at the time of this review. The T3 files in the Composer and Project/terminal sections were fetched and read at the pinned commit (the `ChatComposer.tsx` fetch covered only its first ~100 KB of 156 KB); V4 comparisons are by targeted source search, not by running the apps.

The T3 mobile references below are from its native mobile source. They are useful
design and behavior evidence, but do not prove what the T3 web app supports in a
mobile browser. V4 mobile references describe its responsive browser path.

Codex and Claude support uploaded file paths in the first message. On the home server, a V4 model whose catalog confirms image input can select images and start a message from this screen. The browser saves original bytes locally, creates a confirmed session, copies and uploads the images, then submits through the session-bound receipt path. Unconfirmed sends remain held for review in that conversation; they do not replay automatically. This uses an owner-bound durable creation request on supported Unix servers. Intact copies of the same source revision derive the same creation ID across tabs; the server rejects differing inputs for that ID. This is deduplication, not atomic cross-tab start admission. A deliberate new-task action renews an unchanged source revision with an IndexedDB compare-and-swap. The copy and cleanup fence revisions and retain changed drafts; lost storage or interrupted cleanup can require manual review. Image hashing has a local SHA-256 fallback when SubtleCrypto is unavailable; random IDs still require the browser's cryptographic random generator. Browser tests cover an insecure HTTP origin, reload, image-only starts, account changes and lost responses; a disposable real backend confirms session creation, upload and message admission with no configured provider key. Real provider delivery remains unverified. **Checked against T3 `ChatComposer.tsx` (first ~100 KB of 156 KB read).** T3 also offers `@` suggestions for paths, threads and pull requests, folder/file drop, a paste-as-text shortcut, prompt-history recall and multiple-model drafts; V4's start view has no thread/PR mentions or prompt history found. |
