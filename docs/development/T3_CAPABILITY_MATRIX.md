# T3 capability comparison

This is a **source inventory**, not a tested feature-parity or visual-design
certification. The T3 reference is pinned to
[`5f64c5eb299a23d278ef043c416bd4dc801bc53c`](https://github.com/pingdotgg/t3code/tree/5f64c5eb299a23d278ef043c416bd4dc801bc53c).
V4 references are to the shared, uncommitted working tree inspected during this
review, not to the Tailscale deployment. Changes made concurrently can invalidate
these observations. A row marked **Partial** establishes only the capabilities
named in that row; it does not establish equivalent semantics, availability or
visual similarity. **Unknown** means the relevant behavior was not established.

The T3 mobile references below are from its native mobile source. They are useful
design and behavior evidence, but do not prove what the T3 web app supports in a
mobile browser. V4 mobile references describe its responsive browser path.

## Composer and conversation

| Capability | T3 reference | V4 source evidence and remaining comparison |

| New-thread composition | [Composer](https://github.com/pingdotgg/t3code/blob/5f64c5eb299a23d278ef043c416bd4dc801bc53c/apps/web/src/components/chat/ChatComposer.tsx). | **Partial.** [V4 start view](../../frontend/src/components/WorkspaceStartView.jsx) selects project, agent, model and worktree placement, with branch discovery and a manual base ref. Codex and Claude support uploaded file paths in the first message. On the home server, a V4 model whose catalog confirms image input can select images and start a message from this screen. The browser saves original bytes locally, creates a confirmed session, copies and uploads the images, then submits through the session-bound receipt path. Unconfirmed sends remain held for review in that conversation; they do not replay automatically. This uses an owner-bound durable creation request on supported Unix servers. Intact copies of the same source revision derive the same creation ID across tabs; the server rejects differing inputs for that ID. This is deduplication, not atomic cross-tab start admission. A deliberate new-task action renews an unchanged source revision with an IndexedDB compare-and-swap. The copy and cleanup fence revisions and retain changed drafts; lost storage or interrupted cleanup can require manual review. Image hashing has a local SHA-256 fallback when SubtleCrypto is unavailable; random IDs still require the browser's cryptographic random generator. Browser tests cover an insecure HTTP origin, reload, image-only starts, account changes and lost responses; a disposable real backend confirms session creation, upload and message admission with no configured provider key. Real provider delivery remains unverified. |

## Verification and remaining scope

- This matrix is not exhaustive. It does not audit every T3 feature, provider,
  desktop-shell API, deployment mode, accessibility behavior or settings page.
  In particular, inspect external integrations, MCP apps, notifications, usage
  limits, multi-agent interfaces, desktop updates, keyboard shortcuts, project
  previews and import/export before claiming complete parity.
- Source references do not demonstrate working live APIs, permission handling,
  native provider capability or phone keyboard/microphone behavior. Test each
  important action in isolated integrated desktop and mobile browser flows;
  record real-device results separately.
- The user's first delegation milestone is read-only. V4's read-only child and
  outbox foundations are not evidence of a functioning agent delegation flow.
- Preserve the existing owner, approval, privacy, and recovery boundaries when
  matching user-visible capabilities. Do not infer that a T3 feature requires
  weakening them.
