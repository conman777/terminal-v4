# User image frontend integration

The coherent source candidate connects the shared image controller and native draft store to the real desktop/mobile composers and accepted-user renderer. Current 533 scratch-build evidence now supports bounded ordinary three-transport flows, originals recovery, unknown-send faults and selected lifetime paths as described below. This is candidate evidence, not an installed-release update or complete image-feature verification.

## Frozen send input

`useStructuredSession.sendMessage(rawText, readyAttachments)` requires an owned V4 conversation on the authenticated configured home API. A promoted native store must commit the exact body and its real Blob pins before image transport; ready descriptor metadata alone cannot authorize Send or construct a DB as a fallback. Paired environments and optional legacy adapters reject image sends. Physical loopback is not a frontend requirement. Healthy legacy text remains synchronous with no image DB open; text-only callers retain `/input`, trim and transport-newline behavior, including after image-store promotion.

Both parents pass the canonical session's `aiType` and `model`. An exact catalog model entry with `imageInput === true` is required for image preparation and immediately before POST; missing/false metadata and unknown custom models are blocked. Provider defaults never supply image authority. Account, full configured-home URL, environment, session and render-time model-selection epochs fence async work, including A→B→A transitions. Model changes do not reset the shared socket or transcript.

The image route receives exactly `{requestId,text,attachments}` at `/api/structured/sessions/{id}/attachments/send`. An empty image-message text is valid. Each ordered descriptor contains exactly `attachmentId`, `artifactId`, `mimeType`, `bytes`, and `name`. Validation requires a canonical lowercase UUID, a lowercase SHA256 artifact ID, PNG/JPEG/GIF/WebP MIME, 1 byte through 8 MiB per image, 1–255 UTF-8 bytes for its display name, no control characters or slashes in that name, at most eight references, and at most 16 MiB total. Repeated references count repeatedly against both limits. Every array position must contain a descriptor; sparse lists are rejected on either side of receipt equality. Names are preserved, never filesystem authority.

Before any asynchronous preparation or HTTP, the caller's descriptors are copied into immutable ordered metadata. New image text maps CRLF to LF, then trims only the declared Rust whitespace boundary set: U+0009–000D, U+0020, U+0085, U+00A0, U+1680, U+2000–200A, U+2028, U+2029, U+202F, U+205F, and U+3000. NEL trims; BOM remains and stops trimming behind it. No NFC conversion or appended transport newline occurs.

The raw projection, cloned ordered refs, original draft revision and ordered local IDs are captured synchronously before the first catalog await. The stable composer facade then awaits native `prepareIntent` commitment of the immutable UUID/body/pins. Raw draft text remains separate. A different unresolved intent cannot be overwritten by changed text, images or a text-only attempt; accepted cleanup preserves newer raw text and selected images. Unpromoted text-to-text replacement retains its existing behavior. Legacy localStorage writers use observed-value readback, which is not an atomic cross-window transaction.

**Check previous send** is receipt/local-cleanup recovery only. It remains available without image bytes or a positively image-capable current model. **Retry previous send** GETs the original receipt first. Only 404 permits rechecking current model admission and original pinned bytes before posting the exact frozen serialized body. A404 never authorizes new identity, reordered images or text-only fallback. Every async result is fenced to its originating view/selection. Mount, hydrate, online/login and model changes do not automatically upload, send, look up receipts or cancel attachments; catalog metadata reads and local recovery admission are separate.

Acceptance and lookup require ordinary request/turn/message/sequence identity plus exact `input:{text,attachments}`. Any previously held proof fixes those core IDs and image input before local confirmation. Only native `quota` or `unavailable` cleanup errors may report accepted with local cleanup pending. Identity mismatch, corrupt or unknown confirmation errors reject without transcript adoption and never enter the generic HTTP-uncertainty GET/reconfirmation path. Stale model completion still releases its original send lease. Canonical accepted-user events validate image metadata before React adoption; malformed metadata produces a bounded error without partial text-only adoption or intent cleanup.

## Draft persistence and upload

The facade preserves its existing identity and methods across lazy promotion into IndexedDB. Its native scope is `[ownerId, fullHomeUrlIncludingPathAndTrailingSlash, environmentKey, sessionId]`. Raw text, ordered local records, actual Blobs and a frozen intent are committed through the native store; metadata-only localStorage is never a Blob durability fallback. See [User image draft storage](V4_USER_IMAGE_DRAFT_STORE.md) for transactions and proof/cleanup phases.

Add image, picker/paste/drop, Remove and Retry upload use one shared controller. A new batch commits locally before upload; an immutable upload UUID/generation commits before HTTP; a matching ready receipt commits before readiness. Failures keep visible input and block Send. An unsaved failed Add retains the exact original File objects in memory, with no reload-durability claim. A different batch is rejected before replacing those associations, even when names/MIME/sizes match; local-only removal prunes the corresponding original, and explicit Retry uses only the remaining original objects/order. Native hashing/validation remains authoritative.

The controller shares work and local state between same-scope view leases. Controlled-port tests cover this ownership contract; the App currently reconciles duplicate pane session assignments away, so this does not establish a persistent same-session split view in the public interface. Unsubscribing is not closing; final view release aborts/fences its transport and storage work without deleting saved recovery data. Each view owns and revokes its own preview URLs. Unconfirmed remote removal stays a durable removal job until explicit cancellation proof; a pending-send pin is not cancelled by draft removal.

Sidebar selection now applies the existing `shouldInitializeWorkspacePane` predicate inside the same `handleSelectSession` event, in addition to the existing effect. When its guards allow, the active single pane follows a visible selected session. In a multiple-pane layout it initializes only an eligible empty active pane; occupied active panes and another pane’s assignment stay protected. One committed-DOM regression identity passed, with 11 selection/pane cases and the full 1,340-case frontend gate separately observed. Those unit/component results do not establish the still-unexecuted compiled same-provider selection-race check.

## Recovering missing originals

A historical v1 image intent may have exact canonical metadata/UUID but no Blobs. Native hydration reads that pending request and missing-pin list without completing promotion. A current writable owned/home view may admit a guarded local `legacy`/`copy_committed` recovery promotion when no conflicting local operation is active. A read-only view cannot authorize it. Admission is bounded to the owning native/view epoch; retirement aborts/closes that writer, and an old promise cannot revive through ABA or overlap a returning writer. Failure keeps original evidence and holds originals controls. This local preparation performs no image upload, message POST, receipt GET or cancellation.

**Choose original images** reveals numbered missing-pin rows. Each row opens a separate, purpose-bound **Choose original image** picker; duplicate occurrences remain separate slots in the original pin order. Selected Files are transient shared choices, not yet saved and not claimed to survive reload. Metadata is checked on selection; **Save original images** invokes native typed-byte/hash verification and an atomic local restore. That commit preserves the existing request UUID, serialized body, ordered descriptors, local/upload IDs and newer draft. It performs no upload, receipt lookup or message send. Check or Retry remains a separate explicit action after local restoration.

Restoration does not require positive image-model capability, while Retry after 404 still does. Read-only/inactive/paired, account/home/environment/session/model changes and changed request/authority/pin generations fence chooser and save callbacks. Final view release drops transient choices. A failed restore keeps the frozen request and a visible recoverable state; matching accepted proof can still be checked without restoring bytes. Imported raw text whose source cannot be proven is not automatically cleared.

## Picker, previews and accepted images

The same `DesktopStatusBar.userImages` presentation is mounted in TerminalPane and MobileShell. Add image uses a multiple `Choose images` input restricted to PNG/JPEG/GIF/WebP; ordered File ingress delegates to the shared controller rather than a filesystem screenshot route. Mixed plaintext is passed unchanged at the controlled selection. Owned Enter uses the same raw controlled text as button Send; legacy Enter retains live DOM-value behavior. Chooser opening leases bind purpose, view, request/pin generation and slot; stale results are discarded. Saving, saved-on-device, uploading, ready, failure, removal-unconfirmed and missing-byte states remain distinct. CSS supplies 44px minimum action targets; actual rendered hit-testing/overflow is a separate compiled-interface gate.

Accepted user text is canonical event/receipt content. `V4UserImages` reads only authenticated session attachment content from validated typed refs. It verifies exact MIME/byte count and `SHA256(UTF8('v4-image-v1\0' + mimeType + '\0') || bytes)` before creating a Blob URL; ordinary raw-byte SHA256 is a different identity. Visibility gates reads. Invalid/paired/unavailable content stays a placeholder; scope/auth/session change or unmount aborts reads and releases only that view's URLs. Supplied URIs, filesystem paths and base64 journal payloads are never image sources.

A queued local preview can outlive successful pin cleanup. A missing row which is unretained by matching current and saved native heads still rejects its read, but does not replace the current public error or publish another snapshot. Retained missing pins, changed authority/revision, prior errors and corrupt bytes are not silently cleared or broadly suppressed; see the storage policy below.
